## 二、为什么不用「点插」而是「巡检 + 状态跃迁」

任务进入终态的地方有六七处：rclone job 回调、目录 worker、转封装、跨账号转移、解压、卡住看门狗、低速重连用尽。
在每一处插一句「发通知」看起来最直接，但：

1. 新增一条终态路径（以后再加重试/中转）忘了插，就静默不通知，且没有任何地方能发现；
2. 没法统一去重，用户点「停止」和「故障停止」也分不开；
3. 单测只能覆盖到具体那几处分支。

改成常驻线程每 5 秒读一次 `jobs.json`，比较「上一轮见过的终态」与「这一轮的终态」：

```
notify_loop()  → 每 NOTIFY_SCAN_SEC(5s) 调 notify_scan()
                  → 首次运行只登记（seeded=True），一条都不发
                  → 之后新的去重键才发，一批之间 sleep NOTIFY_SEND_GAP(1s) 防限流
                  → 发送失败也写进去重表，避免同一任务每 5 秒重试刷屏
```

代价是最坏晚 5 秒才知道任务结束 —— 对一个下载器无所谓，换来的是「任何新增终态路径都自动被覆盖」。

## 三、事件判定口径（关键）

| 任务终态 | 条件 | 是否推送 |
| --- | --- | --- |
| `done` | — | ✅ 标题「云梭｜下载完成：<名>」 |
| `error` | `error` 非空 | ✅ 标题「云梭｜任务失败：<名>」 |
| `stopped` | `error` 非空 | ✅ 任务失败（额度用尽 / 卡住看门狗 / 低速重连用尽 / 重启中断都落在这里） |
| `stopped` | `error` 为空 | ❌ 用户自己点的停止，推了就是噪音 |
| `running` / `queued` / `paused` / `stopping` | — | ❌ 非终态 |

去重键：`"<任务id>|<state>|<bytes>|<error 前 60 字>"`

- 同一终态重复扫描 → 同键 → 不重复发；
- 点「继续」后 `bytes` 变了、或错误文案变了 → 换键 → 重新推（这是刻意的，第二次失败值得知道）；
- 状态文件 `DATA_DIR/notify-state.json`（容器内 `/app/notify-state.json`，宿主 `/vol1/docker-apps/console/notify-state.json`），最多保留 400 条，滚旧丢新。

## 八、遗留与下次可做

1. **文件统计口径**：`notify_content` 里「文件」一行对 v2 目录任务用 `filesDone/filesTotal/filesFailed`，对 rclone 老任务这些字段可能是 0，正文会显示「0/0」。要不要按 `kind` 分支渲染，尚未决定。
2. **审计能力**：`notifystate` 目前只给已发条数，前端看不到「最近发过哪几条」。若要把最近 N 条通知的标题/时间暴露出来，需在 `notify-state.json` 的值里加标题字段（现在只存时间戳）。
3. **通知细分**：目前失败原因只作正文，标题统一「任务失败」。若以后要按「额度用尽 / 网络 / 磁盘」分类推不同标题，扩 `notify_title` 即可。
4. **多接收人**：PushPlus 支持 `topic`（群组编码），一行代码即可加，但需要你建群组并给编号，暂未做。
5. **部署习惯**：本次起 NAS 换文件走「`docker cp` 到容器 /tmp → `docker exec -u 0` 写 bind mount」。之前 FileTerm 桌面端今天没在运行（`FILETERM_APP_UNAVAILABLE`），`~/.ssh/config` 里 `Host nas`（`admin` + `~/.ssh/fnos_admin`）可直连，远程脚本用 base64 走 `bash -s` 规避 PowerShell 引号问题。

## 九、v4.11 补修（同日晚，两处通知噪音）

### 9.1 部署 v4.11 之前的 v4.10 就暴露了两个问题

**问题一：重启容器 → 一串「任务失败」。**
11:12 重启 v4.10 后，日志立刻出现 `已发送 2 条任务通知`。查去重表，发的是两条
`stopped|…|控制台重启过，下载已中断（点「继续」会跳过已完成文件接着传）`。
原因：v4.10 的口径是「带 error 的 stopped = 故障停止」，而重启中断恰好带 error。升级一次就发一串失败，显然不对。

**问题二：老任务正文写「文件：0/0 个」。**
rclone 老任务与单文件任务没有 `filesDone` / `filesTotal`，`notify_content` 里 `("%d/%d") if total` 的分支落到 `else`，
渲染成 `0/0`，读起来像下失败了。

### 9.2 改法

- `notify_event`：`stopped` 且 error 以 `("控制台重启过", "守护进程重启过")` 开头 → 返回 `None`，不推。
  三种重启文案（下载中断 / 解压中断 / 转移中断、守护进程重启）都被这个前缀覆盖。
  真正的故障停止（额度用尽 / 卡住看门狗 / 低速重连用尽）文案不带这些前缀，照旧推。
  界面上状态与错误原文不变，只是不发微信。
- `notify_content`：「文件」行改为按数据可用性渲染 —— 有总数→`5/7 个（失败 2）`；只有完成数→`3 个（失败 1）`；
  单文件且成功→`1 个`；都没有→**整行不显示**。
