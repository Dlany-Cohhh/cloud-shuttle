## 2. 总体执行结构：五个阶段，顺序不可颠倒

```
阶段 0  机械基线 ──→ 阶段 1  完整性审计 ──→ 阶段 2  Bug 猎杀 ──→ 阶段 3  结构重构 ──→ 阶段 4  重构后回归 ──→ 阶段 5 (可选) 拆包
(锁定起点)          (AI·提示词 A/C)         (AI·提示词 B/D)      (提示词内置于施工图)     (复跑 0/1，接口对账自动化)     (提示词内置于施工图)
   │                    │                       │                    │                        │
   └── 任何一步失败：回到上一阶段的绿色提交，不带着红灯前进 ──┘
```

**为什么是这个顺序**：

1. **先审计、后重构**：行号是 AI 审计证据的坐标系。先在稳定代码上把接口断链和真 bug 找出来并修掉，重构时才有干净基线；反过来做，所有审计结论的行号全部作废。
2. **完整性先于 bug**：接口断链（前端调用了后端没有的 action）是确定性缺陷，一次全量比对就能穷举；bug 猎杀是抽样排查，先摘掉确定性果实再打猎，避免把断链误报成 bug。
3. **重构夹在两轮验证之间**：重构本身不修 bug、不改语义，AST 等价断言 + 341 用例是它的验收；重构后接口清单从手工提取变成 `sorted(HANDLERS)` 自动输出，审计成本反而下降。

## 3. 阶段详解

### 阶段 0 · 机械基线（半小时，一次性）

**目的**：锁定可复现的起点，后面所有「有没有变坏」都和它比。

**操作**：

```powershell
cd E:\A-MyProject\cloud-shuttle
python -m py_compile "download-console.py"                                  # 语法
Get-ChildItem tests\test_*.py | ForEach-Object { python $_.FullName }        # 22 文件 341 用例（discover 不可用）
git status --short ; git log --oneline -5                                    # 记录当前提交
```

**注意**：`tests/` 没有 `__init__.py`，`python -m unittest discover` 会报 *not importable*，必须逐文件循环。

**验收关卡**：341 用例全绿；未提交改动要么提交、要么明确留观。**红灯时禁止进入阶段 1。**

**产物**：本文件第 7 节的基线记录表。

---

### 阶段 1 · 完整性审计（AI 执行，半天）

**目的**：穷举「承诺了但没兑现」的断链。这类问题不需要抽样，全量比对一次讲清。

**任务 1.1 接口对齐**：用 `AI-CODE-REVIEW-PROMPTS.md` 提示词 A。三个集合全量比对——前端 `api("...")` 字面量（97 处）、后端 90 个 action 分支、`docs/API.md` 声明。产出差异表：孤儿调用 / 死接口 / 未文档化 / 承诺未实现 / 命名不一致。

**任务 1.2 前端一致性**：用提示词 C。后端返回字段名 vs 前端读取字段名、Vue 模板幽灵字段、事件绑定方法名三类断链。

**验收关卡（AI 结论的关卡，不是 AI 自己说了算）**：

1. 每条发现必须带 `文件:行号` + 原文片段，缺证据的退回重查；
2. 逐条人工复核，分成三档：**确认缺陷 / 待验证 / 误报**；
3. 确认缺陷当场修复（多半是一两行的事），修复后跑全量测试；
4. 「待验证」的写进第 7 节追踪表，进入阶段 2 一并排查。

**产物**：接口差异表（修复后归零或记录豁免理由）+ 修复提交。

---

### 阶段 2 · Bug 猎杀（AI + 人工闭环，1–2 天）

**目的**：在稳定代码上排查语义级 bug。**按子系统分块，绝不整文件投喂。**

**任务 2.1 子系统排查**：用提示词 B，换四次符号清单，一次审一个域。每次都带「已知设计取舍」声明，防止 AI 把无鉴权、无数据库当缺陷刷屏：

| 轮次 | 子系统 | 核心符号（行号为 v4.20 基线） | 重点视角 |
|---|---|---|---|
| B-1 | 任务生命周期 | `launch_job`(2511)、`stop_job_group`(2672)、`sweep_orphan_groups`(2695)、`wait_worker_exit`(2762)、`auto_retry_scan`(1908) | 状态机非法跃迁 / 两代 worker 并存 / 收尾误判 |
| B-2 | 通知 | `notify_scan`(1746)、`notify_sig`(1624)、`_notify_state_save`(1650) | 去重失效、已完成任务重播（v4.19 刚修过，查回归） |
| B-3 | 命名落盘 | `safe_basename`(2240)、`dedupe_dest`(2043)、name_map 系(2296–2392) | 超长截断、同名冲突、跨卷映射错位 |
| B-4 | 网络与代理 | `rc`(372)、`refresh_proxy_rc`(711)、`_rc_http_call`(348) | 重试风暴、超时叠加、凭证失效误判 |

**任务 2.2 diff 审查常态化**：以后每次写代码提交前，用提示词 D 审未提交 diff（意图复述 / 回归点 / 对称修改三问）。

**任务 2.3 闭环（核心，不允许跳过）**：

```
AI 报缺陷 → 5 分钟内写最小复现（脚本 / 断言 / 对照日志）
   ├─ 复现成功 → 修复 → 用提示词 E 补回归测试（沿用 tests/ 现有风格）→ 跑全量 341 用例
   └─ 复现失败 → 回告 AI「按现有代码不成立，原因 X」→ 复核后撤销或降级为待验证
```

**验收关卡**：每条报告都走完闭环（修复+回归测试，或撤销+记录）；回归测试全绿。

**产物**：bug 清单（含撤销记录）+ 回归测试文件 + 修复提交。

---

### 阶段 3 · 结构重构（1 天）

**目的**：把 2,114 行、90 分支的 `api()` 铺平成注册表 + 90 个 `@action` 函数；路径常量归一。**不新增文件、不碰分发协议。**

**操作**：完全按 `STRUCTURE-OPTIMIZATION-GUIDE.md` 第 4.1、4.2 节执行，要点重申：

1. 逐分支机械搬移，**只搬不改**；发现可疑代码记 TODO 另开提交；
2. AST 等价断言：一次性脚本逐分支比对改造前后函数体的 `ast.dump()`；
3. 注册顺序 = 原分支顺序，diff 最小化。

**验收关卡**：

1. `api()` ≤ 40 行，90 个 handler 与原分支 AST 等价；
2. 341 用例全绿 + 前端五页冒烟（概览 / 云盘预览 / 任务 / 设置 / 检查更新）；
3. `sorted(HANDLERS)` 与 `static/app.js` 的 action 字面量对账（此时若阶段 1 已修齐，应零差异）。

**回滚**：单文件内部改动，`git checkout -- download-console.py` 整体回退。

---

### 阶段 4 · 重构后回归（半天）

**目的**：证明重构没有引入任何行为变化，并让接口审计升级为自动化。

**操作**：

1. 复跑阶段 0 全套命令（基线必须仍全绿）；
2. 用 `print(sorted(HANDLERS))` 直接生成后端接口清单，与前端 97 处调用、`docs/API.md` 三方脚本对账——**这一步从此不再需要 AI**；
3. 抽 10 个高频 action（jobs / settings / remotes / start / stop / health / updatecheck…），前后端各跑一次比对响应 JSON；
4. 用提示词 D 对重构 diff 本身做一轮审查（意图 / 回归 / 对称修改三问）。

**验收关卡**：以上四项全过，重构提交打 tag（如 `v4.21-refactor`）。

**产物**：接口对账脚本（可加入 `scripts/`，长期使用）。

---

### 阶段 5 · 切叶子模块 / 拆包（可选，仅满足触发条件才做）

**触发条件**（满足其一）：出现第二位贡献者；action 超过 150 个；单文件让 AI 工具频繁出错。**行数本身不是理由。**

**操作**：准入条件（目标域对外引用 ≤ 5 符号）、拆包顺序、协议七处同步、发版前强制演练，全部按 `STRUCTURE-OPTIMIZATION-GUIDE.md` 第 4.3、4.4 节执行，此处不展开。

**验收关卡**：`build_release.py` 出包成功 + 一次完整的「旧版容器 → 新版 Release」在线更新演练（含回滚），四项全过才算完成。

## 9. 一句话执行令

**先锁基线 → 用提示词 A/C 穷举断链 → 用提示词 B/D 闭环猎杀 → 铺平 `api()` 并用 AST 断言等价 → 复跑基线并把接口对账变成脚本 → 满足触发条件才拆包、拆包必演练。**
